# Bandit Level 21 → Level 22

## Level Goal

A program is running automatically at regular intervals from `cron`, the time-based job scheduler. Look in `/etc/cron.d/` for the configuration and see what command is being executed.

---

## Finding the Cron Job

First, I listed the contents of `/etc/cron.d/` to locate the configuration file for this level:

```bash
cat /etc/cron.d/cronjob_bandit22
```

Output:

```text
@reboot bandit22 /usr/bin/cronjob_bandit22.sh &> /dev/null
* * * * * bandit22 /usr/bin/cronjob_bandit22.sh &> /dev/null
```

This configuration tells us:
* `* * * * *` → The job runs every minute of every hour, day, month, and week.
* `bandit22` → The job executes under the user privileges of `bandit22`.
* `/usr/bin/cronjob_bandit22.sh &> /dev/null` → The script being executed, with stdout and stderr redirected to `/dev/null`.

---

## Inspecting the Cron Script

Next, I inspected the shell script being executed by the cron job:

```bash
cat /usr/bin/cronjob_bandit22.sh
```

Output:

```bash
#!/bin/bash
chmod 644 /tmp/t7O6lds9S0RqQh9aMcz6ShpAoZKF7fgv
cat /etc/bandit_pass/bandit22 > /tmp/t7O6lds9S0RqQh9aMcz6ShpAoZKF7fgv
```

---

## Understanding the Script

Breaking down the script's commands:

1. **`chmod 644 /tmp/t7O6lds9S0RqQh9aMcz6ShpAoZKF7fgv`**
   * Grants world-readable permissions (`rw-r--r--`) to the file in `/tmp`. This ensures that any user on the system (including `bandit21`) can read it once written.

2. **`cat /etc/bandit_pass/bandit22 > /tmp/t7O6lds9S0RqQh9aMcz6ShpAoZKF7fgv`**
   * Reads the password file for `bandit22` and redirects (`>`) the output into a hardcoded file in `/tmp`.

Because the script runs as `bandit22`, it has the permissions required to read `/etc/bandit_pass/bandit22` and write it to the publicly readable file in `/tmp`.

---

## Retrieving the Password

Since the job runs every minute, the file in `/tmp` already exists and contains the updated password. I simply read the target file directly:

```bash
cat /tmp/t7O6lds9S0RqQh9aMcz6ShpAoZKF7fgv
```

This printed the password for Level 22.

## What I Learned

### 1. Cron Job Configurations
System-wide cron jobs stored in `/etc/cron.d/` follow a standard crontab format specifying time intervals, user accounts, and target commands.

### 2. Hardcoded Temporary Files
Using predictable, hardcoded filenames in shared public directories like `/tmp` creates security risks, allowing unauthorized users to inspect data meant to be protected.

### 3. File Permissions (`chmod 644`)
* `6` (Owner): Read + Write
* `4` (Group): Read-only
* `4` (Others): Read-only

Setting world-readable permissions allowed `bandit21` to read the password output generated by the `bandit22` process.

---

## Key Takeaway

> **Always trace scheduled tasks to their source scripts to identify exposed system information or predictable file writes.**

Execution pipeline:

```text
/etc/cron.d/cronjob_bandit22
        ↓
Executes /usr/bin/cronjob_bandit22.sh (as bandit22)
        ↓
Reads /etc/bandit_pass/bandit22
        ↓
Writes output to /tmp/t7O6lds9S0RqQh9aMcz6ShpAoZKF7fgv
        ↓
Read file directly as bandit21
```
